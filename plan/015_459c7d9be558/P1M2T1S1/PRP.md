## Why

- **Step 1 of the §9.10.1 stagecoach delegation.** The descriptive commit message will be generated by
  **delegating to the real `stagecoach` binary** (replacing the in-process re-implementation that
  drift-prone acquired a hardcoded `Co-Authored-By: Claude` trailer — incident 1). Before P1.M2.T2.S1
  can exec it, the pipeline must (a) ship the binary as a transitive npm dep and (b) resolve its path.
  This task is (a)+(b); T2.S1 is the exec.
- **"Shipped with this tool" — no external runtime dependency.** PRD §9.10.1 mandates stagecoach come
  via the `stagecoach-ai` npm package whose `postinstall` downloads the per-platform native binary —
  so `npm install hacky-hack` brings it along: no separate install, no `PATH` lookup, no Go toolchain
  for end users. Declaring the dep makes that true; the resolver consumes it.
- **Fail-fast, never silent.** §9.10.1 acceptance: "Removing the stagecoach binary at runtime produces
  a clear, actionable error (not a silent fallback to an in-process generator)." The resolver throws
  `AgentError` (the established commit-path error type) on a missing binary/dep, so a broken install
  surfaces as one actionable startup/error line rather than a silent regression to the in-process path.
- **Mirrors the package's own shim.** Resolving the same `~/.stagecoach/versions/<ver>/<plat>/stagecoach`
  path the `bin/stagecoach.js` shim uses keeps the pipeline and the user's `git stagecoach` alias
  pointed at the identical binary (no divergence, no double-install).
- **Standalone & scoped.** S1 = one new module + its test + the dep. It does NOT touch `git-commit.ts`
  (T2.S1/T3.S1 rewrite it) and is file-disjoint from the parallel P1.M1.T4.S1 (prompt text).
- **Out of scope (hard boundary):** the `stagecoach --dry-run --single` exec + provider/model/`--format`
  forwarding (P1.M2.T2.S1), removing the in-process `commit-message-agent.ts` (P1.M2.T3.S1/S2), the
  commit-identity structural guard (P1.M3), any edit to `src/utils/git-commit.ts`, `docs/*.md`
  (Mode B = P3.M1.T1.S2 updates package.json install note), `PRD.md`, `tasks.json`, `prd_snapshot.md`.

```ts
/**
 * Resolve the absolute path to the stagecoach native binary (PRD §9.10.1).
 *
 * @remarks
 * Shipped with this tool — `stagecoach` is declared as an npm dependency
 * (`stagecoach-ai`), whose `postinstall` downloads the per-platform native Go
 * binary (goreleaser cross-builds linux/darwin/windows × amd64/arm64) into
 * `~/.stagecoach/versions/<version>/<goos>-<goarch>/stagecoach`. `npm install`
 * therefore brings stagecoach along transitively: no separate install, no `PATH`
 * lookup, no Go toolchain for end users. This resolver mirrors the package's own
 * `bin/stagecoach.js` shim so the pipeline and `npx stagecoach` resolve the SAME
 * binary. The cache root is overridable via `STAGECOACH_CACHE_DIR`.
 *
 * @returns The absolute path to the stagecoach native binary.
 * @throws {AgentError} If the `stagecoach-ai` dependency is not installed, or the
 *   native binary is missing (postinstall blocked / not yet installed). Never a
 *   silent fallback — a missing binary is an actionable startup error (§9.10.1).
 *
 * @example
 * const bin = resolveStagecoachBinary();
 * spawnSync(bin, ['--dry-run', '--single'], { stdio: 'inherit', env: process.env });
 */
import { createRequire } from 'node:module';
import { existsSync, readFileSync } from 'node:fs';
import os from 'node:os';
import path from 'node:path';
import { AgentError } from './errors.js';

const nodeRequire = createRequire(import.meta.url);

/**
 * Compute the goreleaser platform/arch segment + binary name for the current host.
 *
 * @remarks
 * goreleaser names use Go's `GOOS`/`GOARCH` (e.g. `windows`/`amd64`), NOT Node's
 * `process.platform`/`process.arch` (`win32`/`x64`). Exported for direct unit testing.
 */
export function platformArch(): {
  goos: string;
  goarch: string;
  binaryName: string;
} {
  const goos = process.platform === 'win32' ? 'windows' : process.platform;
  const goarch = process.arch === 'arm64' ? 'arm64' : 'amd64'; // x64 → amd64
  const binaryName = goos === 'windows' ? 'stagecoach.exe' : 'stagecoach';
  return { goos, goarch, binaryName };
}

export function resolveStagecoachBinary(): string {
  // 1. Read the installed stagecoach-ai version (the cache is versioned by it).
  let version: string;
  try {
    const pkgJsonPath = nodeRequire.resolve('stagecoach-ai/package.json');
    version = (JSON.parse(readFileSync(pkgJsonPath, 'utf-8')) as { version: string }).version;
  } catch {
    throw new AgentError(
      'stagecoach-ai dependency not installed. Run `npm install` (it brings the stagecoach ' +
        'native binary via postinstall; no separate install / PATH needed). See §9.10.1.'
    );
  }

  // 2. Compute the per-platform cache path (mirrors bin/stagecoach.js exactly).
  const { goos, goarch, binaryName } = platformArch();
  const cacheRoot =
    process.env.STAGECOACH_CACHE_DIR || path.join(os.homedir(), '.stagecoach', 'versions');
  const binPath = path.join(cacheRoot, version, `${goos}-${goarch}`, binaryName);

  // 3. Fail fast with an actionable error if the binary is missing (postinstall blocked).
  if (!existsSync(binPath)) {
    throw new AgentError(
      `stagecoach native binary not found at ${binPath}. Run \`npm install\` to install it ` +
        '(no separate install / PATH needed). See §9.10.1.'
    );
  }
  return binPath;
}
```

## Anti-Patterns to Avoid

- ❌ Don't use bare `require.resolve('stagecoach-ai/…')` — the project is ESM (`"type": "module"`).
      Use `createRequire(import.meta.url)` (node:module), the codebase's established pattern
      (logger.ts:48-51). `import.meta.resolve` is only stable Node ≥20.6 — don't rely on it.
- ❌ Don't silently fall back when the binary is missing — §9.10.1 acceptance explicitly requires a
      clear, actionable error (not a fallback to the in-process generator). Throw `AgentError`.
- ❌ Don't hardcode the stagecoach-ai version in the resolver — read it from the installed package's
      package.json (the cache is versioned by it; mirroring the shim's `pkg.version` keeps the resolver
      correct across stagecoach-ai bumps without a code change).
- ❌ Don't use Node's `process.platform`/`process.arch` values directly in the path — goreleaser names
      use Go's GOOS/GOARCH (`windows`, `amd64`). Map `win32`→`windows` and `x64`→`amd64` in `platformArch()`.
- ❌ Don't forget `npm install` after editing package.json — declaring the dep without installing leaves
      it absent; the resolver would throw the dep-not-installed `AgentError` in production.
- ❌ Don't touch `src/utils/git-commit.ts` (the in-process stagecoach agent there; T2.S1/T3.S1 rewrite
      it) or `src/agents/commit-message-agent.ts` (T3.S1 removes it). S1 = resolver + dep ONLY.
- ❌ Don't do the `stagecoach --dry-run --single` exec in S1 — that's T2.S1. S1 only resolves the path.
- ❌ Don't skip the hermetic test mocks — without `vi.mock('node:module')` + `vi.mock('node:fs')`, the
      tests depend on stagecoach-ai being installed AND the binary being on disk, making them flaky and
      leaving branches (dep-missing, binary-missing) uncoverable. 100% coverage requires the mocks.
- ❌ Don't run the full `npm run test:run` as the gate — orthogonal pre-existing failures. Gate on
      typecheck + lint + format:check + the targeted suite + the install.
- ❌ Don't edit `docs/*.md` — the package.json install note + broader docs sync is P3.M1.T1.S2 (Mode B).
