## The Changes

### Change A — §9.10 (new): Commit Generation & Agent Tool Safety

A new cross-cutting section consolidating three concerns. It adds:

- **§9.10.1 — Commit-Message Generation (stagecoach delegation, message-only).**
  The descriptive commit message is generated by delegating to the **`stagecoach`
  binary** (npm `stagecoach-ai` dependency, per-platform native binary downloaded
  at `postinstall`), invoked **message-only** as `stagecoach --dry-run --single`
  — NOT by an in-process LLM agent. The pipeline retains ownership of the commit
  itself (staging, the atomic commit, the task-prefix position layer,
  `restore_critical_files`, retry/fallback). Provider/harness + `PRP_COMMIT_STYLE`
  are forwarded to the binary. **There must never be a hardcoded attribution,
  trailer, or footer anywhere in the commit path.**
- **§9.10.2 — Commit-Identity Structural Guard.** `formatCommitMessage` (and the
  whole commit path) MUST NEVER emit a `Co-Authored-By:` trailer, `Generated-by`
  footer, machine author, or identity injection, in any mode. The §5.1 loophole
  ("unless an explicit style layer below adds one") is removed. A **self-source-scan
  test** walks all production `src/` (skipping test files and the guard's own file),
  failing the build if any non-comment line contains a forbidden identity literal
  (`Co-Authored-By`, `noreply@anthropic.com`, `Generated with [Claude Code]`,
  `🤖 Generated`, `GIT_AUTHOR_*`/`GIT_COMMITTER_*` env literals, `user.name`/
  `user.email` git-config args). The prior bug-locked behavioral test
  ("PRESERVES the Co-Authored-By trailer") is **inverted** to assert absence.
- **§9.10.3 — Agent Tool-Access Scoping & Remote-Mutation Prohibition.** Agent
  tool access is scoped **by role** (Research/Planner/Coder → no `bash`, read-only
  `git_status`/`git_diff`; Commit agent → no `bash`, `git_commit` only; Validation
  → `bash` allowed but **denylisted**). The bash tool refuses
  remote/default-branch-mutating commands (`git push`, `git remote`, `git update-ref`,
  `git config`, `gh repo …`, `gh api -X PATCH|POST|DELETE`, `curl`/`wget` to
  `api.github.com`, any `default_branch`) before exec, failing closed on ambiguous
  matches. Remote-mutating ops are **never** exposed as any agent tool, in any role,
  and are added to §5.2 "Universal Forbidden Operations."

### Change B — §5.1 (new blocks): Snapshot-Based Atomic Single-Commit + ARG_MAX-safe staging + baseline `.gitignore` scaffolding

§9.10.1's "the pipeline retains ownership of the commit itself" rests on a new
commit subsystem specified in §5.1:

- **Snapshot-based atomic commit via git plumbing:** `git write-tree` (freeze the
  index into an immutable tree) → `git commit-tree -p <parent> -m <msg> <tree>`
  (dangling commit) → `git update-ref HEAD <new> <expected-old>` (CAS advance).
  Guarantees: atomicity (any non-success path leaves HEAD + index byte-for-byte
  unchanged), snapshot fidelity, commit-identity transparency (no identity
  injection), no shell interpolation. Edge cases handled: rootless repo, unresolved
  merge conflicts, HEAD-moved-during-generation (CAS refuses; surface recovery
  recipe, never force), generation-timeout/SIGINT rescue (print `TREE_SHA` +
  manual recovery).
- **ARG_MAX-safe staging:** stage by pathspec (`git add -A`/`git add .`); where an
  explicit filtered set is needed, chunk the path list under an `ARG_MAX` byte
  budget per `git add` call. Prevents `spawn E2BIG` on unignored `node_modules/`
  trees that silently strand task status.
- **Baseline `.gitignore` scaffolding:** the Architect's decomposition MUST include
  a first, dependency-root scaffolding subtask that creates — or, if one exists,
  **extends (never overwrites)** — a baseline `.gitignore` (dependency dirs, build
  output, OS/IDE cruft) before any feature subtask. `plan/`, `PRD.md`, and task
  files MUST NOT be gitignored. Mirrored as a cross-reference in **§4.1 step 4**.

### Change C — §4.5.1 (new): Format-Nudge Recovery (Missing Result Envelope)

A missing/unparseable agent output contract is a _transport/contract miss_, not a
code or planning problem, and is recovered **in place** (re-prompt the same agent
with a format reminder, bounded by `FORMAT_NUDGE_MAX` default 2, in a budget
isolated from `maxFixAttempts` and `ISSUE_RETRY_MAX`), across three variants:

- **Coder result envelope** — `PRPExecutor.#parseCoderResult` flags `formatFailure`
  distinctly from a real `error`/`issue`; nudge the same Coder Agent to emit only
  the JSON envelope (don't repeat the work); re-parse; on exhaustion hard-fail as a
  normal `error`.
- **Researcher PRP file write** — if `retryAgentPrompt` retries still leave the PRP
  file missing, `PRPGenerator.#nudgeResearcherToWrite` re-prompts "the file at
  `<path>` is still MISSING — write the complete PRP now" up to `FORMAT_NUDGE_MAX`.
- **Architect / backlog schema** — `FixCycleWorkflow.runStandardBreakdown` validates
  the backlog immediately after read (every Subtask `context_scope` must pass
  `ContextScopeSchema`); on failure nudges the Architect with the specific zod
  issues, and if still non-conforming **auto-heals** each `context_scope` back into
  valid form (section order preserved, missing pieces defaulted).

### Change D — Terminology / catalog cleanup (cosmetic, no behavior)

- New **Contents** entry `17. [Commit Generation & Agent Tool Safety]`.
- New **§9.1** bullet: `Commit-Message Generation: stagecoach — the stagecoach-ai
  npm dependency … invoked message-only …`.
- §4.2 step 4, §5.1 (Smart Commit Resilience / Format / Style), §9.2.2: reword
  `stagecoach`-as-in-process-tool references to `Smart Commit` / "commit-message
  agent", aligning §5.1/§9.2.2 with the new §9.10 binary-delegation model.
