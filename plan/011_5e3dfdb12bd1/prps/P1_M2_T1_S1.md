# PRP for P1.M2.T1.S1

## Objective

Add an exported PURE function `isNegatedFileExistenceGate(command: string): boolean` that conservatively detects the unambiguous negated file/directory-existence gate forms (leading `!` before `test`/`[` and inner `!` inside `test`/`[` over `-f`/`-e`/`-d`), plus a green table-driven unit test. This is the REQ-G2 detector half (PRD §9.9.2 G2.1/G2.2/G2.3); it is consumed by sibling S2 which wires it into PRPExecutor.#runValidationGates(). S1 touches ONLY the new function + its test — no executor, model, or prompt edits.

## Context

## Goal

**Feature Goal**: Ship an exported, pure, zero-dependency TypeScript function `isNegatedFileExistenceGate(command: string): boolean` that returns `true` ONLY for the unambiguous negated file/directory-**existence** gate forms, and a green table-driven vitest unit test that pins the exact behavior table from PRD §9.9.2 (G2.1/G2.2/G2.3). This is the conservative detector that the executor (sibling task S2) will use to deterministically skip/neutralize cached or legacy non-monotonic gates.

**Deliverable**: One new source module `src/agents/gate-semantics.ts` exporting `isNegatedFileExistenceGate`, and one new test file `tests/unit/agents/gate-semantics.test.ts` with a table-driven `it.each([...])` block. No other file is modified.

**Success Definition**: `npx vitest run tests/unit/agents/gate-semantics.test.ts` is green; `npm run typecheck` is clean; the function is exported and importable; the behavior table matches PRD §9.9.2 G2.1 (detect+skip negated existence), G2.2 (never negated content), G2.3 (ambiguous → `false` → executes normally) row-for-row.

## Why

- PRD §9.9.1 documents a regression: `PRPExecutor.#runValidationGates()` re-runs every researcher-authored gate command as a batch on the terminal filesystem state. A **negative file-existence gate** (`! test -f src/hooks/index.ts`) encodes a scope boundary that is permanently false once a sibling task commits the file, making the item **permanently unwinnable** (no terminal state satisfies it short of deleting a committed deliverable).
- REQ-G2 requires the executor to **neutralize** such gates at runtime — a conservative relaxation that repairs cached/legacy PRPs without regeneration. REQ-G2 splits cleanly: the **detector** (this task, S1) is a pure function, and the **wiring** into `#runValidationGates` is sibling S2. Keeping them separate makes the detector trivially unit-testable in isolation (no agent/BashMCP mocking) and lets S2 be a small, reviewable integration.
- For whom: the pipeline itself — so a cached PRP containing `! test -f X` can no longer stall an item forever.

## What

A pure detector with this exact contract:

```ts
export function isNegatedFileExistenceGate(command: string): boolean;

```

- Returns `true` ONLY for the two unambiguous negated-existence forms (PRD §9.9.2 G2.1):
  - **Leading bang** before the `test`/`[` builtin: `! test -f X`, `! [ -e X ]`
  - **Inner bang** inside the `test`/`[` builtin: `test ! -f X`, `[ ! -d X ]`
  - where the flag is one of the POSIX existence flags `-f` (regular file), `-e` (exists), `-d` (directory).
- Returns `false` for everything else, specifically (G2.2/G2.3):
  - negated **content** checks: `! grep -q TODO src/x.ts` (G2.2 — must execute normally)
  - positive existence/content checks: `test -f x`, `grep -q foo x`
  - unrelated commands: `npm test`
  - **ambiguous** commands: `test -n foo`, `test foo` (G2.3 — when in doubt, return `false` so the executor runs the gate normally rather than silently suppressing a legitimate one)

### Implementation Patterns & Key Details

```typescript
const LEADING_NEGATED_EXISTENCE = /^\s*!\s+(?:test|\[)\s+-[fed]\b/;
const INNER_NEGATED_EXISTENCE = /^\s*(?:test|\[)\s+!\s+-[fed]\b/;
export function isNegatedFileExistenceGate(command: string): boolean {
  if (typeof command !== 'string' || command.trim() === '') return false;
  return LEADING_NEGATED_EXISTENCE.test(command) || INNER_NEGATED_EXISTENCE.test(command);
}

```

import { describe, expect, it } from 'vitest';

  it.each<[command: string, expected: boolean]>([
    ['! test -f src/hooks/index.ts', true],

## Anti-Patterns to Avoid

- ❌ Don't wire the detector into `#runValidationGates` here — that is sibling S2. S1 ships ONLY the pure function + test.
- ❌ Don't edit `src/core/models.ts` — the `ValidationGate` schema already supports `manual`/`command:null`; the neutralization is runtime-only (impl-status §B.3).
- ❌ Don't over-match (G2.3). Compound expressions (`test -f x -a ! -f y`), wrappers (`bash -c '...'`), and `-n`/`-z` string tests MUST return false. A non-match means "execute normally", which is the safe default.
- ❌ Don't match negated content (`! grep -q ...`) — that is G2.2's explicit exclusion and must execute normally.
- ❌ Don't add runtime dependencies (zod/logger/groundswell) — the function must be pure string analysis so the unit test needs zero mocking.
- ❌ Don't co-locate in `prp-executor.ts` and then import the function in a standalone test without mocking — that drags in groundswell/BashMCP/checkpoint-manager. Use the dedicated `gate-semantics.ts` module (or, if co-locating, add the tests inside `prp-executor.test.ts` where the mocking already lives).
