## Why

PRD §9.9.1 documents two permanent-failure regressions where the Researcher emitted non-monotonic gates the executor then mechanically re-ran on the terminal filesystem state:
- **geoform-hack `P1.M3.T1.S1`** — gate `! test -f src/hooks/index.ts`, but `src/hooks/index.ts` is the committed deliverable of sibling `P1.M3.T1.S3`. Permanently unwinnable.
- **pi-nvim-bridge-hack `P1.M1.T1.S1`** — gates 1–3 require a spike file to exist while gate 4 is `test ! -f extension/spike.ts`. No single terminal state satisfies both.

REQ-G1 is the **prompt-layer** half of the fix: prevent the Researcher from *emitting* such gates in newly-generated PRPs. (The runtime half — REQ-G2, neutralizing cached/legacy gates — is sibling **P1.M2**; the Builder-side G1.4 is sibling **P1.M1.T2.S1**.) This task is **prompt edits only**, consumed by every future Researcher run and mirrored into `PROMPTS.md` later by **P1.M3.T1.S1** (Mode B doc sync).

```
- **NEVER author a negative file/directory-existence gate (PRD §9.9 G1.1).** A gate MUST NOT assert the *absence* of a path. Forbidden forms include `test ! -f|-e|-d <path>`, `! test -f|-e|-d <path>`, `[ ! -f|-e|-d <path> ]`, and `! [ -f|-e|-d <path> ]`. File/directory existence is owned by the task graph and is non-monotonic across it — a path correctly absent today may be a committed sibling deliverable tomorrow, which would make such a gate permanently unwinnable. (You may still *inspect* for a file's absence during research; just never encode it as a mechanical gate.)
   [ASSERT substrings: 'G1.1', 'test ! -f|-e|-d', '! test -f|-e|-d', '[ ! -f|-e|-d', '! [ -f|-e|-d', plus /non-monotonic/i]
- **Scope boundaries are never shell gates (PRD §9.9 G1.2).** A constraint such as 'this task must not create or modify file X' or 'must not import symbol Y' MUST be expressed either (a) as a **Success Criterion** the coder follows, or (b) as a **`manual: true` Level-4 gate** (Level 4 = Manual/Creative), which the executor skips. Never encode it as a negated-existence shell gate. The executor MUST NOT hard-fail an item on a scope-boundary existence check.
   [ASSERT substrings: 'G1.2', 'Success Criterion', 'manual: true', /Level-4|Level 4/i]
- **Cleanup / throwaway deletion is never a shell gate (PRD §9.9 G1.3).** For spike and throwaway artifacts, the 'delete the artifact' step is a *cleanup instruction*, not a mechanical gate; a 'the artifact is gone' check MUST be emitted as `manual: true`. A `test ! -f <throwaway>` gate is forbidden by G1.1 and doubly forbidden here.
   [ASSERT substrings: 'G1.3', /cleanup instruction/i, 'manual: true']
- **Negated content gates only on a permanent, own-deliverable absence (PRD §9.9 G1.5).** A negated *content* check (`! grep -q 'FORBIDDEN' <file>`) is permitted ONLY when `<file>` is this task's own deliverable AND the asserted absence is permanent once fixed (e.g. 'no `TODO` markers remain', 'no reference to a forbidden symbol'). It MUST NOT assert something about another task's file.
   [ASSERT substrings: 'G1.5', '! grep -q', /own deliverable/i]

```
